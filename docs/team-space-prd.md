# Team Space PRD

## 1. Background

SPEC 4기 러너들이 창업 팀빌딩을 완료함에 따라, 프러너가 러너 팀의 실행 상태를 지속적으로 관리할 수 있는 내부 관리 기능이 필요하다. 기존 공개 페이지의 `Apply` 진입점은 모집 기능 중심이므로, 현재 운영 단계에서는 멤버 전용 팀 관리 페이지로 전환한다.

## 2. Goals

- 프러너가 각 러너 팀의 목표, 진행 상황, CTA를 한 곳에서 확인하고 관리한다.
- 러너 팀은 팀스페이스에서 CTA와 오피스아워 내용을 확인하고 후속 액션을 공유한다.
- 외부인은 팀 관리 페이지에 접근할 수 없도록 한다.
- 기존 로그인 버튼 옆 `Apply` 버튼을 팀 관리 페이지 진입 버튼으로 교체한다.

## 3. Target Users

- 프러너: 전체 팀 현황 관리, CTA 설정, 오피스아워 기록 작성 및 공유
- 러너: 본인 팀스페이스 확인, CTA 진행 상태 업데이트, 오피스아워 내용 열람
- 외부인: 접근 불가

## 4. User Stories

- 프러너는 팀 목록에서 각 팀의 담당 프러너, 팀원, 최신 CTA, 오피스아워 상태를 빠르게 확인한다.
- 프러너는 팀별 팀스페이스에서 CTA를 생성하고 마감일, 담당자, 상태를 관리한다.
- 프러너는 2주마다 진행한 오피스아워의 논의 내용, 결정 사항, 다음 액션을 기록한다.
- 러너는 본인 팀의 CTA와 오피스아워 기록을 확인하고 진행 상태를 업데이트한다.

## 5. Scope

### In Scope

- `/teams` 또는 `/team-space` 멤버 전용 진입 페이지
- 팀 목록, 팀 상세 팀스페이스
- CTA 생성, 수정, 상태 변경, 공유
- 오피스아워 회차별 기록 및 공유
- Navbar의 `Apply` 버튼 대체
- Supabase RLS 및 서버 액션 권한 검증

### Out of Scope

- 외부 멘토 초대
- 실시간 채팅
- 캘린더 자동 예약 연동
- 알림톡/이메일 자동 발송

## 6. Functional Requirements

### Team Management

- 프러너는 팀을 생성하고 팀명, 한 줄 설명, 담당 프러너, 러너 멤버를 설정할 수 있다.
- 러너는 본인이 속한 팀만 열람한다.
- 프러너는 전체 팀을 열람하되, 담당 팀 필터를 제공한다.

### CTA Management

- CTA 필드는 제목, 설명, 담당자, 마감일, 상태(`todo`, `doing`, `done`, `blocked`)를 포함한다.
- 프러너는 모든 CTA를 생성/수정/삭제할 수 있다.
- 러너는 본인 팀 CTA의 상태와 코멘트를 업데이트할 수 있다.

### Office Hours

- 팀별로 2주 단위 오피스아워 기록을 생성한다.
- 기록 필드는 진행일, 참석자, 논의 내용, 결정 사항, 다음 액션, 다음 회차 예정일을 포함한다.
- 최신 오피스아워 기록은 팀스페이스 상단에 노출한다.

## 7. Permissions

- `outsider`: 접근 불가, `/login?redirect=/team-space` 또는 `/`로 이동
- `learner`: 본인 소속 팀만 접근
- `preneur` 또는 `is_admin=true`: 전체 팀 관리 가능
- 모든 mutation은 UI뿐 아니라 server action과 RLS에서 검증한다.

## 8. Success Metrics

- 프러너가 전체 팀 CTA 현황을 1분 이내 확인할 수 있다.
- 각 팀이 2주마다 최소 1개 오피스아워 기록을 남긴다.
- 러너 팀별 CTA 누락 상태를 프러너가 즉시 식별할 수 있다.
